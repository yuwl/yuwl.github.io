5. 一键安装常用开发工具

通过 Docker Compose，我们可以快速搭建一套完整的本地开发环境。本篇提供了一个包含 Nacos 和 Redis 的 docker-compose.yml 示例，并解决了数据持久化和网络通信的问题。

设计思路​

  1. 挂载本地磁盘（Volumes）：持久化数据（如 Nacos 的配置、Redis 的数据）必须挂载到宿主机。
  2. 网络隔离（Networks）：创建一个自定义网络，使工具之间可以通过容器名相互访问。
  3. 模式选择：Nacos 默认使用 standalone（单机）模式启动。

目录结构建议​

建议建立一个专门的目录来存放这些配置：

dev-env/
├── docker-compose.yml
├── nacos/
│   ├── logs/      # 存放日志
│   └── data/      # 存放 Nacos 数据
└── redis/
    └── data/      # 存放 Redis 数据

docker-compose.yml 配置文件​

version: '3.8'

services:
  # --- Nacos (单机版) ---
  nacos:
    image: nacos/nacos-server:v2.2.3
    container_name: dev-nacos
    restart: always
    environment:
      - MODE=standalone
      - SPRING_DATASOURCE_PLATFORM=derby          # V2.2.3+ 必须显式指定为 derby 才能使用内置数据库
      - NACOS_AUTH_ENABLE=true                   # 开启权限校验
      - NACOS_AUTH_IDENTITY_KEY=serverIdentity   # V2.2.0+ 必须配置身份密钥
      - NACOS_AUTH_IDENTITY_VALUE=security       # V2.2.0+ 必须配置身份密钥
      - NACOS_AUTH_TOKEN=SecretKey012345678901234567890123456789012345678901234567890123456789 # 自定义 Base64 令牌
      - JVM_XMS=512m                             # 调小内存
      - JVM_XMX=512m
    ports:
      - "8848:8848"
      - "9848:9848" # gRPC 端口
      - "9849:9849"
    volumes:
      - ./nacos/logs:/home/nacos/logs
      - ./nacos/data:/home/nacos/data
    networks:
      - dev-network

  # --- Redis ---
  redis:
    image: redis:7.0-alpine
    container_name: dev-redis
    restart: always
    command: redis-server --appendonly yes --requirepass "123456" # 开启持久化和密码
    ports:
      - "6379:6379"
    volumes:
      - ./redis/data:/data  # 数据持久化
    networks:
      - dev-network

networks:
  dev-network:
    driver: bridge

关键点说明​

1. Nacos 详解​

  • 端口 8848：控制台访问地址 http://localhost:8848/nacos。
  • gRPC 端口 (9848/9849)：Nacos 2.x 版本必须暴露这两个端口，否则 Spring Cloud 应用连接会报错。
  • SPRING_DATASOURCE_PLATFORM=embedded：为了简单，这里直接使用 Nacos 自带的内嵌数据库。如果你想关联你之前的 MySQL，可以另外配置镜像。

2. 挂载本地磁盘 (Volumes)​

  • 我们将物理机的目录映射到容器内部。在 Windows 上，Docker Desktop 会自动处理。如果你运行 docker-compose up -d，它会自动在当前目录下创建 nacos/ 和 redis/ 文件夹。

2. 网络通信​

  • 同一个 dev-network 下的容器可以互相访问。
  • 比如你的应用如果要连接 MySQL，地址直接填 dev-mysql:3306 即可，不需要填 IP。

3. 如何使用​

  1. 将上述 YAML 代码保存为 docker-compose.yml。
  2. 在当前目录下打开 PowerShell。
  3. 执行启动命令： 
    docker-compose up -d
  4. 查看运行状态： 
    docker-compose ps

常见问题处理：已有旧容器怎么办？​

如果你的 Docker 中已经手动安装并运行了 MySQL 8.0 容器，直接运行 docker-compose up 可能会遇到以下两个问题：

1. 端口冲突 (Port Conflict)​

现象：报错 Bind for 0.0.0.0:3306 failed: port is already allocated。 原因：宿主机的 3306 端口已经被旧容器占用了。 建议：

  • 方案 A：停止并删除旧容器（如果不需要了）：docker stop <旧容器名> && docker rm <旧容器名>。
  • 方案 B：修改 docker-compose.yml 中的端口映射，改用其他端口，例如 "3307:3306"。

2. 容器名称冲突​

现象：报错 The container name "/dev-mysql" is already in use。 原因：你可能之前手动定了一个同名的容器名。 建议：在 docker-compose.yml 中修改 container_name: dev-mysql 为其他不重名的 ID。

3. 数据迁移​

如果旧容器里的数据很重要，建议先备份数据，或者将旧容器的数据卷路径映射到 Compose 的 volumes 配置中。

mysql安装命令​

docker run --hostname=731edc49886f --mac-address=d2:fb:d6:20:d9:55 --env=MYSQL_ROOT_PASSWORD=123456 --env=PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin --env=GOSU_VERSION=1.19 --env=MYSQL_MAJOR=8.0 --env=MYSQL_VERSION=8.0.45-1.el9 --env=MYSQL_SHELL_VERSION=8.0.45-1.el9 --volume=/var/lib/mysql --network=bridge --workdir=/ -p 3306:3306 --restart=no --runtime=runc -d mysql:8.0
