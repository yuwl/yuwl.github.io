

# 14. JDBC

目标：理解 Java 程序是如何连接并操作数据库的，掌握 `PreparedStatement` 防止 SQL 注入，以及连接池的概念。

## 1. 什么是 JDBC？
JDBC 本质上是一套 Java 官方定义的接口 (Interface)。
*   Oracle (Java 的维护者) 规定了“怎么连”、“怎么发 SQL”、“怎么接数据”的标准接口。
*   MySQL、Oracle、PostgreSQL 等数据库厂商负责编写实现这些接口的“实现类”（即 数据库驱动 Jar 包）。
*   好处：Java 程序员只需要学一套 JDBC 接口，就能操作所有类型的数据库。

---

## 2. JDBC 核心四大金刚 (Core Components)

| 类/接口名 | 作用 | 比喻 |
| :--- | :--- | :--- |
| DriverManager | 管理驱动，负责获取连接 | 租车公司 |
| Connection | 表示与数据库建立的连接 | 一辆车 / 一通电话 |
| PreparedStatement | 用于执行 SQL 语句（预编译） | 运货员 / 传话筒 |
| ResultSet | 存放查询回来的结果集 | 货物清单 / 回信 |

---

## 3. JDBC 标准开发步骤 (Standard Steps)

在写代码之前，你需要先在项目中引入 MySQL 的驱动依赖 (如果是 Maven 项目)：
```xml
<dependency>
    <groupId>mysql</groupId>
    <artifactId>mysql-connector-java</artifactId>
    <version>8.0.33</version>
</dependency>
```

### 核心六步走：
1.  加载驱动 (Load Driver)
2.  获取连接 (Get Connection)
3.  获取执行对象 (Get Statement)
4.  执行 SQL (Execute SQL)
5.  处理结果 (Process Result)
6.  释放资源 (Close Resources) - 非常重要！

## 4. 实战代码演示 (最佳实践版)

我们跳过过时的 `Statement`，直接学习企业开发标准的 `PreparedStatement` 和 try-with-resources 写法。

假设数据库中有一张表 `user` (id, username, password)。

### 4.1 查询操作 (SELECT)

```java
import java.sql.*;

public class JdbcQueryDemo {
    public static void main(String[] args) {
        // 1. 数据库连接配置
        String url = "jdbc:mysql://localhost:3306/test_db?useSSL=false&serverTimezone=UTC";
        String user = "root";
        String password = "123456"; // 你的数据库密码

        // SQL 语句，使用 ? 作为占位符
        String sql = "SELECT * FROM user WHERE id = ?";

        // 2. 使用 try-with-resources 自动关闭资源 (Java 7+ 特性)
        // 凡是实现了 AutoCloseable 接口的对象，放在 try() 里，执行完会自动 close
        try (Connection conn = DriverManager.getConnection(url, user, password);
             PreparedStatement pstmt = conn.prepareStatement(sql)) {

            // 3. 设置参数 (填补 ? 的内容)
            pstmt.setInt(1, 101); // 第1个问号，填入整数 101

            // 4. 执行查询，返回结果集
            try (ResultSet rs = pstmt.executeQuery()) {
                // 5. 遍历结果集 (类似迭代器)
                while (rs.next()) {
                    // 根据列名或列索引获取数据
                    int id = rs.getInt("id");
                    String name = rs.getString("username");
                    System.out.println("查询到用户: ID=" + id + ", Name=" + name);
                }
            }

        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}
```

### 4.2 更新操作 (INSERT/UPDATE/DELETE)

更新操作不需要 `ResultSet`，它返回的是一个 `int`，代表受影响的行数。

```java
// ... 省略 import
// 核心逻辑片段
String sql = "INSERT INTO user (username, password) VALUES (?, ?)";

try (Connection conn = DriverManager.getConnection(url, user, password);
     PreparedStatement pstmt = conn.prepareStatement(sql)) {

    pstmt.setString(1, "zhangsan");
    pstmt.setString(2, "secret_pwd");

    // 执行更新，返回影响行数
    int rows = pstmt.executeUpdate(); 
    
    if (rows > 0) {
        System.out.println("添加成功！");
    }

} catch (SQLException e) {
    e.printStackTrace();
}
```

## 5. 重点难点解析

### 5.1 PreparedStatement vs Statement
*   Statement: 用于执行静态 SQL。危险！ 容易产生 SQL 注入漏洞。
    *   *反例*: `"SELECT * FROM user WHERE name = '" + userName + "'"`
    *   如果用户输入 `admin' -- `，SQL 就会变味，导致安全问题。
*   PreparedStatement (推荐): 预编译 SQL。
    *   安全: 使用 `?` 占位符，数据库会将参数视为纯文本，彻底防止 SQL 注入。
    *   高效: 数据库会对预编译的 SQL 进行缓存，多次执行性能更好。

### 5.2 资源释放 (close)
*   数据库连接是昂贵的资源（就像你打电话给 10086，一直占线不挂断）。
*   必须遵循 “后开先关” 的原则：`ResultSet` -> `Statement` -> `Connection`。
*   强烈建议使用 `try-with-resources` 语法（如上代码所示），避免在 `finally` 块中写一大堆 `if (conn != null) conn.close()`。

## 6. 进阶：数据库连接池 (Connection Pool)

在实际项目中，我们绝对不会像上面代码那样，每次执行 SQL 都去 `DriverManager.getConnection()`。
*   原因: 创建和销毁连接非常消耗系统资源和时间。
*   解决: 使用连接池。程序启动时预先创建好一堆连接（比如 10 个），放在池子里。要用的时候从池子里“借”，用完了“还”回池子，而不是关闭。

### 常用连接池
1.  Druid (德鲁伊): 阿里巴巴开源，功能强大，自带监控，国内首选。
2.  HikariCP: Spring Boot 2.0+ 默认内置，号称速度最快。

> 学习建议: 现阶段只需了解连接池解决了什么问题。在学习 Spring/Spring Boot 时，只需要修改几行配置文件就能自动使用连接池。
