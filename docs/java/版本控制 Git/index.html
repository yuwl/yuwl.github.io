16. 版本控制 Git

目标：

  1. 掌握 Git 的核心概念，学会代码备份与版本回退。

🐙 第一部分：Git —— 代码的“时光机”​

1. Git 是什么？​

Git 是一个分布式版本控制系统。

  • 后悔药：代码改崩了？一键回退到昨天下午 3 点的状态。
  • 协作：多人同时修改一个项目，Git 负责合并代码，处理冲突。

2. 核心区域图解​

你需要理解代码流转的四个区域：

  1. 工作区 (Workspace): 你正在写代码的地方（IDEA 打开的文件夹）。
  2. 暂存区 (Index/Stage): 临时存放你准备提交的修改 (git add)。
  3. 本地仓库 (Repository): 安全存放所有历史版本的地方 (git commit)。
  4. 远程仓库 (Remote): 如 GitHub/Gitee，用于云端备份 (git push)。

3. 安装与首次配置​

安装完 Git 后，打开终端 (CMD 或 Git Bash)，必须配置用户名和邮箱（这是你的身份标识）：

git config --global user.name "YourName"
git config --global user.email "your_email@example.com"

4. 常用指令 (由浅入深)​

基础三板斧 (每天都要用)​

  1. git add .
    • 将所有修改过的文件添加到“暂存区”。
  2. git commit -m "备注信息"
    • 将暂存区的内容正式提交到“本地仓库”。注意：必须写备注，且要清晰（如：完成用户登录功能）。
  3. git push
    • 将本地仓库的代码推送到“远程仓库” (GitHub/Gitee)。

初始化与获取​

  • git init: 在当前文件夹初始化一个 Git 仓库（生成隐藏的 .git 文件夹）。
  • git clone [url]: 从远程下载一个项目到本地。

其他重要指令​

  • git status: 查看当前文件状态（哪些红了没 add，哪些绿了没 commit）。
  • git log: 查看提交历史记录。
  • git pull: 拉取远程最新代码并合并到本地（团队开发每天早上的第一件事）。

5. 必须了解：.gitignore 文件​

非常重要！ 并不是所有文件都需要上传到 Git。 例如：编译后的 .class 文件、IDE 的配置文件 (.idea)、Maven 生成的 target 目录。

在项目根目录创建一个名为 .gitignore 的文件，写入以下内容：

# 忽略编译结果
/target/
*.class

# 忽略 IDE 配置文件
.idea/
*.iml
.vscode/

# 忽略日志文件
*.log

💻 第三部分：在 IDEA 中实操 (推荐方式)​

虽然命令行很酷，但初学者强烈建议直接使用 IDEA 图形化操作，效率更高。

1. Maven 实操​

  • 新建项目时：选择 Maven 构建。
  • 添加依赖：在 pom.xml 中粘贴代码，右上角会出现一个小浮窗（Load Maven Changes），点击它（或按 Ctrl+Shift+O），IDEA 会自动下载包。

2. Git 实操​

  • 开启 Git：菜单栏 VCS -> Create Git Repository。
  • 提交代码：点击右上角的绿色对勾 ✔️ (Commit)。
    • 勾选文件。
    • 填写 Message。
    • 点击 Commit。
  • 查看历史：点击底部的 Git 面板，可以看到漂亮的版本树状图。

✅ 阶段练习作业​

  1. Git 练习：
    • 在 Gitee (码云) 或 GitHub 注册账号。
    • 创建一个远程空仓库。
    • 将上面的 Maven 项目代码推送到远程仓库。
    • 尝试修改一行代码，再次 add -> commit -> push，去网页端看看代码有没有更新。
