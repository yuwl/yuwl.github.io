15. 构建工具 Maven

目标：

  1. 理解为什么需要构建工具，掌握 Maven 的依赖管理。

📦 第一部分：Maven —— Java 项目的“大管家”​

1. 为什么需要 Maven？​

在没有 Maven 之前，我们需要手动去网上下载各种 jar 包（例如 MySQL 驱动、工具类），然后复制到项目中。这会导致：

  • 版本混乱：不知道 jar 包具体是什么版本。
  • 依赖冲突：A 包依赖 B 包，B 包依赖 C 包，手动管理非常痛苦。
  • 项目臃肿：项目文件包含大量 jar 包，体积巨大。

Maven 的作用：你只需要告诉它你需要什么（写一段配置），它自动从互联网下载下来，并帮你管理好。

2. 核心概念：G.A.V​

在 Maven 世界里，任何一个 jar 包（依赖）都由三个坐标唯一确定，称为 GAV：

  • GroupId (组织 ID)：通常是域名反写，如 com.google, org.springframework。
  • ArtifactId (项目 ID)：项目的名称，如 spring-boot, mysql-connector。
  • Version (版本号)：如 1.0.0, 3.1.4-SNAPSHOT。

3. 核心文件：pom.xml​

这是 Maven 项目的核心配置文件。

<project>
    <!-- 项目自身信息 -->
    <groupId>com.example</groupId>
    <artifactId>my-first-app</artifactId>
    <version>1.0-SNAPSHOT</version>

    <!-- 📦 依赖管理区：在这里声明你需要的包 -->
    <dependencies>
        <!-- 示例：引入 MySQL 驱动 -->
        <dependency>
            <groupId>mysql</groupId>
            <artifactId>mysql-connector-java</artifactId>
            <version>8.0.33</version>
        </dependency>
        
        <!-- 示例：引入 JUnit 测试框架 -->
        <dependency>
            <groupId>junit</groupId>
            <artifactId>junit</artifactId>
            <version>4.13.2</version>
            <scope>test</scope> <!-- scope表示作用范围 -->
        </dependency>
    </dependencies>
</project>

4. 必做配置：阿里云镜像 (加速下载)​

默认 Maven 从国外中央仓库下载，速度极慢。必须配置国内镜像。 找到 Maven 安装目录下的 conf/settings.xml (如果是 IDEA 自带的 Maven，通常只需在 IDEA 设置里指定一个新的 settings.xml)，在 <mirrors> 标签内添加：

<mirror>
    <id>aliyunmaven</id>
    <mirrorOf>*</mirrorOf>
    <name>阿里云公共仓库</name>
    <url>https://maven.aliyun.com/repository/public</url>
</mirror>

5. 常用命令 (Lifecycle)​

在 IDEA 右侧的 Maven 面板中可以直接双击运行，但需了解原理：

  • mvn clean: 清理，删除生成的 target 目录（编译后的文件）。
  • mvn compile: 编译，将 .java 编译成 .class。
  • mvn package: 打包，生成 jar 或 war 包。
  • mvn install: 安装，将打好的包安装到本地仓库，供其他项目使用。
