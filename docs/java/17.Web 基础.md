

# 17. Web 开发基础

> 核心目标：理解 B/S 架构，看懂 HTTP 协议，掌握前后端数据交互的标准（JSON）。

## 1. 软件架构模式：B/S vs C/S

在 Web 开发中，我们主要关注 B/S 架构。

*   C/S (Client/Server): 客户端/服务器。例如：QQ、英雄联盟、Steam。需要用户下载安装包，更新麻烦，但性能好。
*   B/S (Browser/Server): 浏览器/服务器。例如：淘宝网页版、B站网页版。用户无需安装，有浏览器就能访问，服务端更新，客户端自动同步。
    *   你的位置：你编写的代码运行在 Server（服务端）。
    *   你的客户：是 Browser（浏览器） 或 手机 App。

## 2. HTTP 协议 (重中之重)

HTTP (HyperText Transfer Protocol) 是浏览器和服务器之间沟通的“语言”。后端开发 50% 的调试工作都在看 HTTP 报文。

### 2.1 请求 - 响应模型 (Request - Response)
Web 交互永远是“一问一答”：
1.  Request: 浏览器发起请求（我要看首页）。
2.  Response: 服务器返回响应（这是首页的 HTML 代码）。

### 2.2 HTTP 请求 (Request) 的组成
当你点击一个链接，浏览器发送的数据包包含：
1.  请求行: `GET /index.html HTTP/1.1` (包含 请求方式 和 路径)。
2.  请求头 (Headers): 告诉服务器我的信息（我是什么浏览器、我能接收什么语言、Cookie 等）。
3.  请求体 (Body): POST 请求才有，存放表单数据或 JSON 数据。

常见的请求方式 (Method)：
*   GET: 获取数据 (查询)。参数通常拼接在 URL 后面 (`?id=1&name=jack`)。
*   POST: 提交数据 (新增)。参数在请求体中，更安全，无长度限制。
*   PUT: 修改数据。
*   DELETE: 删除数据。

### 2.3 HTTP 响应 (Response) 的组成
服务器处理完后返回：
1.  响应行: `HTTP/1.1 200 OK` (包含 状态码)。
2.  响应头: 告诉浏览器数据类型（是图片还是文字）、缓存策略等。
3.  响应体: 真正的页面内容或数据。

必须死记硬背的状态码 (Status Code)：
*   200: 成功 (OK)。
*   400: 客户端请求参数有误 (Bad Request)。
*   401/403: 没登录或没权限 (Unauthorized/Forbidden)。
*   404: 找不到资源 (Not Found) —— *通常是你路径写错了*。
*   500: 服务器内部错误 (Internal Server Error) —— *你的 Java 代码抛异常了*。

## 4. 数据交互格式：JSON
过去用 XML，现在 JSON (JavaScript Object Notation) 统治世界。它是前后端传输数据的标准格式。

### 为什么是 JSON？
*   轻量级，节省带宽。
*   Java 对象 `<==>` JSON 字符串 的转换非常方便（后续会学 Jackson 库）。

### 语法规则
*   `{}` 代表对象。
*   `[]` 代表数组。
*   `key: value` 键值对。

示例：一个包含学生信息的 JSON
```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "id": 101,
    "name": "张三",
    "isStudent": true,
    "hobbies": ["编程", "篮球", "睡觉"]
  }
}
```

## 5. Web 服务器：Tomcat
*   作用：Java 写好的类（.class）自己是动不起来的，也不能直接被浏览器访问。Tomcat 是一个容器，它监听端口（默认 8080），接收 HTTP 请求，转交给你的 Java 代码处理，再把结果返回给浏览器。
*   注意：在 Spring Boot 阶段，Tomcat 被内置了，你不需要单独安装配置它，但你要知道它的存在。

在现在的 Java 开发（特别是 Spring Boot）中，你几乎看不到 Servlet 和 JSP 的原始代码了。但是，它们是整个 Java Web 的基石。

## 6. Servlet (Server Applet)
Servlet 是运行在 Web 服务器（如 Tomcat）上的 Java 小程序。它的唯一作用就是：接收请求 -> 处理业务 -> 返回响应。

### 6.1 Servlet 的本质
在没有 Spring 框架之前，我们需要手动编写一个类继承 `HttpServlet`，并重写方法来处理 HTTP 请求。

```java
// 这是一个原始 Servlet 的样子
@WebServlet("/hello") // 映射路径：当浏览器访问 /hello 时，执行这个类
public class HelloServlet extends HttpServlet {

    // 处理 GET 请求
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        // 1. 接收参数
        String name = req.getParameter("name");
        
        // 2. 处理业务
        System.out.println("接收到名字：" + name);
        
        // 3. 返回响应
        resp.setContentType("text/html;charset=UTF-8");
        resp.getWriter().write("<h1>Hello, " + name + "</h1>");
    }
    
    // 处理 POST 请求
    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        doGet(req, resp); // 通常交给 doGet 处理
    }
}
```

### 6.2 核心对象 (必须掌握)
这两个对象贯穿了整个 Java Web 开发，Spring MVC 只是把它们包装得更好了。

*   `HttpServletRequest` (请求对象): 封装了浏览器发来的所有信息。
    *   获取参数: `request.getParameter("username")`
    *   获取头信息: `request.getHeader("User-Agent")`
    *   请求转发: `request.getRequestDispatcher("/b.jsp").forward(req, resp)` (内部跳转，URL 不变)
*   `HttpServletResponse` (响应对象): 用于给浏览器发送数据。
    *   输出内容: `response.getWriter().write(...)`
    *   重定向: `response.sendRedirect("/login.html")` (外部跳转，URL 会变)

### 6.3 Servlet 生命周期 (面试必问)
Tomcat 是如何管理 Servlet 的？
1.  加载与实例化: 默认情况下，第一次有请求访问该 Servlet 时，Tomcat 创建它的对象（单例）。
2.  初始化 (`init`): 对象创建后立即执行，只执行一次（用于加载资源）。
3.  服务 (`service`): 每次 请求都会执行。它会判断是 GET 还是 POST，然后分发给 `doGet` 或 `doPost`。
4.  销毁 (`destroy`): 服务器关闭或重启时执行。

> 🛑 重点难点：线程安全问题
> Servlet 在 Tomcat 中是单例的（只有一个对象）。
> 如果 1000 个人同时访问，这 1000 个线程用的是同一个 Servlet 对象。
> 绝对不要在 Servlet 中定义成员变量来存储用户数据！ (否则张三会看到李四的数据)。

## 7. JSP (Java Server Pages)
JSP 看起来像 HTML，但里面可以写 Java 代码。

### 7.1 为什么会有 JSP？
Servlet 写页面太痛苦了（要在 Java 里拼写 HTML 字符串）。JSP 允许你在 HTML 里嵌入 Java 代码。

### 7.2 JSP 的本质
JSP 本质上就是一个 Servlet！
当你第一次访问 `index.jsp` 时，Tomcat 会自动把它“翻译”成一个 Java 类（`index_jsp.java`），这个类继承了 HttpJspBase (也就是 HttpServlet)。

### 7.3 基本语法 (了解即可)
```jsp
<!-- HTML 代码 -->
<html>
<body>
    <!-- 1. Java 脚本片段: 写逻辑 -->
    <% 
        String name = "Java";
        int age = 18;
    %>

    <!-- 2. Java 表达式: 输出变量到页面 -->
    <h1>你好，<%= name %></h1>
    
    <!-- 3. EL 表达式 (Expression Language): 现代 JSP 写法，替代上面的 <%= %> -->
    <h2>年龄：${age}</h2>
</body>
</html>
```

### 7.4 四大作用域 (Scope)
理解数据能存活多久：
1.  Page: 当前页面有效。
2.  Request: 一次请求内有效（转发后依然有效，最常用）。
3.  Session: 一次会话内有效（用户登录状态存这里）。
4.  Application: 整个服务器运行期间有效（全局变量）。

## 8. MVC 模式的演变

理解这段历史，你就能明白为什么现在要学 Spring Boot。

### 阶段 1: Model 1 (纯 JSP)
*   逻辑和页面全写在 JSP 里。
*   缺点: 代码像意大利面条，极其难以维护。

### 阶段 2: Model 2 (Servlet + JSP)
*   Servlet (Controller): 负责接收请求，处理逻辑。
*   JSP (View): 只负责展示数据。
*   JavaBean (Model): 数据对象。
*   缺点: Servlet 太多了，每个业务都要写一个 Servlet，配置繁琐。

### 阶段 3: Spring MVC (现代模式)
*   DispatcherServlet: Spring 提供了一个“超级 Servlet”，它拦截所有请求。
*   Controller: 我们只需要写普通的 Java 类加注解 (`@Controller`)，DispatcherServlet 会自动调用我们的方法。
*   前后端分离: 也就是我们现在主流的写法。后端不再返回 JSP 页面，而是直接返回 JSON 数据，页面由前端框架 (Vue/React) 渲染。

## 📝 总结与学习建议

1.  Servlet:
    *   要学: 理解 Request/Response 常用方法，理解 Session 和 Cookie 的区别，理解 Servlet 生命周期。
    *   不学: 不用深究 `web.xml` 的复杂配置（现在都用注解了）。
2.  JSP:
    *   要学: 认识 `<% %>` 和 `${}` 语法，能看懂老代码。
    *   不学: 不要花时间去背 JSP 标签库 (JSTL)，新项目中不会用的。
3.  下一步: 
    *   理解了 Servlet 的痛点（手动获取参数麻烦、手动类型转换麻烦、输出 JSON 麻烦），你就会发现 Spring MVC 是多么的香！
