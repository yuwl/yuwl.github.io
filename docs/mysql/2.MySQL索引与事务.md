# 2. MySQL 高级特性

## 1. 索引 (Index)
索引主要用于提高查询效率。

### 索引分类
- **主键索引 (Primary Key)**: 唯一且不为空。
- **唯一索引 (Unique)**: 唯一可以为空。
- **普通索引 (Index)**: 基本的索引。
- **全文索引 (FullText)**: 用于搜索文本。

### 索引原理
MySQL 索引主要基于 **B+Tree** 数据结构：
- **非叶子节点**：仅存储键值（索引列的值）和指针，不存储实际数据，因此可以容纳更多索引，树的高度较低（通常 3-4 层）。
- **叶子节点**：存储了所有的键值以及对应的行数据（聚簇索引）或主键值（二级索引），且叶子节点之间通过**双向链表**连接，极大地提高了范围查询的效率。

### 聚簇索引 vs 非聚簇索引
- **聚簇索引 (Clustered Index)**：索引结构和数据记录在一起，InnoDB 的主键索引就是聚簇索引。
- **非聚簇索引 (Secondary Index)**：索引结构只包含主键值，查找数据需要“回表”查询（除非是覆盖索引）。

### 索引优化原则
1. **最左前缀法则**：联合索引要遵守最左匹配，中间不能跳过。
2. **覆盖索引**：尽量只查询建立了索引的列，减少 `SELECT *` 以避免回表。
3. **索引下推 (ICP)**：在索引遍历过程中，对索引包含的字段先做判断，过滤掉不符合条件的记录，减少回表次数。
4. **小表驱动大表**：使用 `EXPLAIN` 分析查询计划，确保索引生效。

### 索引失效的情况
- 使用 `LIKE '%abc'` (左模糊)。
- 在索引列上进行函数计算。
- 类型转换导致的失效。

## 2. 事务 (Transaction)
事务是数据库操作的最小工作单元。

### ACID 特性
- **A (Atomicity) 原子性**: 事务要么全部成功，要么全部失败。
- **C (Consistency) 一致性**: 数据库从一个一致性状态变为另一个一致性状态。
- **I (Isolation) 隔离性**: 并发事务之间相互隔离。
- **D (Durability) 持久性**: 事务提交后，修改是永久性的。

### 隔离级别
1. 读未提交 (Read Uncommitted)
2. 读已提交 (Read Committed)
3. 可重复读 (Repeatable Read) - **MySQL 默认**
4. 串行化 (Serializable)
